# AI 玩贪吃蛇（DQN）

用 Stable-Baselines3 的 DQN 训练一只会玩贪吃蛇的 AI：15×15 棋盘、12 维手工特征观测、动作掩码硬约束。
当前最好模型平均能吃 **58 个食物**（20 局评测），最好一局 76 个；通关（填满棋盘）需要 224 个。

## 快速开始

```bash
pip install -r requirements.txt
python train_snake.py            # 训练（已有模型则继续训练）
python train_snake.py --watch    # 看 AI 玩（默认最佳模型）
```

## 实测成绩

同一批 20 个随机种子（700–719），每局最多 3000 步：

| 模型 | 观测 | 训练步数 | 平均食物 | 最低 | 最高 |
|---|---|---|---|---|---|
| **最佳（默认）** | 绝对逃生比率 | 1.12M | **58.2** | 39 | 76 |
| 原型 | 绝对逃生比率 | 540k | 43.1 | 18 | 61 |
| 实验版 | 相对空间 room | 1.15M | 46.4 | 18 | 71 |

## 设计要点

- **动作掩码**：`mask_wrapper.py` 把"会立即撞墙/撞身体"的动作替换成合法动作，以硬约束方式避免 AI 送死。
- **观测（12 维）**：食物相对方向、四向危险、蛇身长度占比、逃生空间、四向可达自由度。
- **奖励**：接近食物 + 方向对齐 − 步罚；吃食物按"吃完后还剩多少相对空间"给 17.5~70（永不为负）；
  死亡 −20；填满棋盘 +2000；每吃 25 个食物额外 +100。
- **通关判定**：蛇身填满棋盘即 `terminated`，展示分额外加 1000 万（与训练奖励解耦）。
- **步数上限 3000**：蛇可能绕圈永远不死，没有上限会把评估/训练挂住。

## 踩过的坑（都写在提交历史里）

1. **通关奖励不能给 1e7**：值函数只有 ±65 的量级，1e7 学不动，还会污染整条轨迹的目标值。
2. **相对空间 `room` 反而不如绝对比率**：room 在实战中几乎恒为 1.0（均值 0.978），特征饱和、信息量低。
3. **食物随机数必须用 `self.np_random`**：早期用全局 `random`，`reset(seed=...)` 完全没生效，
   导致"同一批种子"每次摆的食物都不同，所有配对比较都是噪声。
4. **探索率 0.02 + buffer 10 万 + batch 64 是负收益**：同样 500k 步，47 → 40.6，已回退。

## 已知局限

距离通关（224 个食物）还很远。继续堆训练步数收益已明显递减（500k → 1.15M 只涨 4 个食物），
下一步更值得尝试的是课程学习（随机初始长度/小棋盘渐进），而不是继续调奖励。
